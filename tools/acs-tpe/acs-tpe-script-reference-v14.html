ACS TPE Migration — Script Reference

Customer Documentation  ·  ACS Direct Routing → Teams Phone System  ·  Generated 2026-05-05

01   Overview

The ACS TPE (Teams Phone Enablement) migration toolkit moves phone numbers from ACS Direct Routing to Teams Phone System (Direct Routing) with zero downtime. It also supports full rollback at any stage.

Systems Touched

Systems Involved

Microsoft Teams
DR gateway, voice routes, resource accounts, phone assignments
Dynamics 365 (D365)
Phone number type, resource account link, CCaaS sync
ACS (Azure Communication Services)
SIP trunk enable/disable, route patching
Microsoft Entra ID
Domain registration for RA UPN suffix

02   Prerequisites

Required Tools

  • PowerShell 5.1 or later ($PSVersionTable.PSVersion)
  • Azure CLI — az login with subscription access
  • MicrosoftTeams PS module — Install-Module MicrosoftTeams
  • Microsoft.Graph PS module — Install-Module Microsoft.Graph

Required Permissions

  • Teams Admin (Global Admin or Teams Service Admin)
  • D365 System Administrator or customizer role
  • Azure Contributor on the ACS resource
  • Entra ID Domain Administrator (for Step 4 domain registration)
Teams Authentication: The MicrosoftTeams module does not cache tokens across PowerShell processes. Each new PS session requires Connect-MicrosoftTeams -UseDeviceAuthentication — authenticate at https://login.microsoft.com/device before running any script.

04   Config Generation

New-AcsTpeConfig-v14.ps1
Setup

Auto-generates the config JSON by querying Azure, D365, and ACS. Only the -Domain parameter is required — all other values are discovered automatically.

Parameters

ParameterRequiredDescription
-DomainRequiredCustom domain for Resource Account UPNs, e.g. cbg-voice.contoso.com
-OutputPathOptionalPath to write config JSON. Default: .\new-acs-tpe-config-v14.11.0.json
-SubscriptionIdOptionalOverride Azure subscription. Default: current az CLI subscription
-D365OrgUrlOptionalOverride D365 org URL. Default: discovered via Global Discovery Service
-PolicyNameOptionalTeams Voice Routing Policy name. Default: acs-tpe-migration
-UsageNameOptionalTeams PSTN Usage name. Default: acs-tpe-pstn-usage
-RouteNameOptionalTeams Voice Route name. Default: acs-tpe-voice-route
-DryRunOptionalDiscover and display all values without writing the config file

Examples

# Auto-discover everything (only domain needed) .\New-AcsTpeConfig-v14.ps1 -Domain "cbg-voice.contoso.com" # Dry run — show discovered values without writing file .\New-AcsTpeConfig-v14.ps1 -Domain "cbg-voice.contoso.com" -DryRun # Override D365 org URL (useful when Global Discovery doesn't list your org) .\New-AcsTpeConfig-v14.ps1 -Domain "cbg-voice.contoso.com" -D365OrgUrl "https://myorg.crm10.dynamics.com"
Output: Writes new-acs-tpe-config-v14.11.0.json (gitignored — contains credentials). Keep this file in the working directory; all other scripts reference it via -ConfigPath.

05   Full Migration

Invoke-ACS-TPE-Full-Migration-v14.ps1
Migration 11 Steps

End-to-end migration from ACS Direct Routing to Teams Phone System. Runs steps 1–11 sequentially. Supports resume from any step via -StartAtStep.

Migration Steps

  • 1
    Export ACS Trunks
    Reads current ACS SIP trunks and routes, writes acs-export.json. Used by Toggle and Undo scripts for state restoration.
  • 2
    Register Teams Gateway (Zero-Downtime)
    Registers the SBC FQDN as a Teams DR gateway via New-CsOnlinePSTNGateway. ACS trunk is temporarily disabled, then immediately re-enabled after gateway registration.
  • 3
    Create PSTN Usage, Voice Route & Routing Policy
    Creates acs-tpe-pstn-usage, acs-tpe-voice-route (pattern from D365 phone numbers), and acs-tpe-migration voice routing policy.
  • 4
    Register Domain in Entra ID
    Registers the custom domain (e.g. cbg-voice.contoso.com) in Entra ID so Resource Account UPNs can use that suffix. Skipped if domain is already the default.
  • 5
    Validate SBC Gateway, Routes & Policies
    Read-only verification that gateway, route, PSTN usage, and routing policy were created correctly. No changes made.
  • 6
    Upload DR Phone Numbers to Teams
    Calls New-CsOnlineDirectRoutingTelephoneNumberUploadOrder for each number discovered from D365. Polls up to 2 minutes for Activated/Unassigned status. Skips gracefully if number already exists.
  • 7
    Create Resource Accounts (RAs)
    Creates one Teams Resource Account per phone number (UPN: acs-tpe-ra-<number>@<domain>). Object IDs saved to ra-objectids.json. Retries up to 5× for replication lag.
  • 8
    Assign PHONESYSTEM_VIRTUALUSER Licenses
    Assigns Teams Phone Resource Account license to each RA. Polls until license provisioning is confirmed before proceeding.
  • 9
    Assign DR Phone Numbers to RAs + D365 Backup
    Assigns each phone number to its RA via Set-CsPhoneNumberAssignment. Backs up D365 phone number state to d365-phone-backup.json. Triggers D365 CCaaS sync.
  • 10
    Cut Over to Teams
    Calls Toggle-AcsTeamsRouting-v14.ps1 to flip routing: ACS trunk → disabled, Teams gateway → enabled. This is the live cutover moment.
  • 11
    Update D365 Phone Number Types + Sync
    Calls Invoke-MigrateTpsPhoneNumber-v14.ps1 per number to set D365 type → TPS, link Teams RA, and trigger CCaaS_SynchronizePhoneNumbers.

Parameters

ParameterRequiredDescription
-ConfigPathRequiredPath to the generated config JSON
-DryRunOptionalShow all planned actions without making any changes
-StartAtStepOptionalResume from a specific step (1–11). Default: 1
-StopAfterStepOptionalStop after this step. Default: 11
-AutoConfirmOptionalSkip interactive confirmation prompts

Examples

# Always dry-run first .\Invoke-ACS-TPE-Full-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -DryRun # Full migration steps 1–11 .\Invoke-ACS-TPE-Full-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json # Resume from step 7 (e.g. after fixing an RA creation failure) .\Invoke-ACS-TPE-Full-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -StartAtStep 7 # Run only steps 7–9 (RA creation through number assignment) .\Invoke-ACS-TPE-Full-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -StartAtStep 7 -StopAfterStep 9

06   Undo / Full Rollback

Undo-ACS-TPE-Migration-v14.ps1
Rollback

Reverses the full migration (steps 9→1) and restores the environment to a clean pre-migration state. Steps 10–11 are reversed by Invoke-FlipToACS-v14.ps1 and must be run first.

Run order: Always run Invoke-FlipToACS-v14.ps1 first (to reverse steps 10–11), then run this script to reverse steps 9→1.

Undo Steps (reverse order)

  • 9
    Remove Phone Number Assignments
    Unlinks phone numbers from RAs. Restores D365 phone number state from d365-phone-backup.json. Triggers D365 sync.
  • 8
    Remove PHONESYSTEM_VIRTUALUSER Licenses
    Removes Teams Phone Resource Account licenses from all RAs created during migration.
  • 7
    Delete Resource Accounts
    Deletes all Teams Resource Accounts created during migration (from ra-objectids.json). Backs up objectids file with timestamp.
  • 6
    Remove DR Phone Numbers from Teams
    Removes phone numbers from the Teams DR pool. Restores D365 phone records to ACS state.
  • 4
    Remove Registered Domain from Entra ID
    Removes the custom domain registered in Step 4. Skipped if domain is the default or still in use. Requires explicit DELETE confirmation.
  • 3
    Remove Voice Routing Policy, Route & PSTN Usage
    Removes acs-tpe-migration policy, acs-tpe-voice-route, and acs-tpe-pstn-usage. Only removes objects created by the migration — pre-existing routes are untouched.
  • 2
    Remove Teams DR Gateway, Re-enable ACS Trunk
    Removes the Teams DR gateway registration for the SBC FQDN. Re-enables the ACS trunk (with original routes from acs-export.json). Only removes gateways added during migration — pre-existing gateways are skipped.
  • 1
    Backup acs-export.json
    Archives acs-export.json with timestamp (file kept for reference).

Parameters

ParameterRequiredDescription
-ConfigPathRequiredPath to the config JSON
-DryRunOptionalShow all planned removals without making any changes
-StartAtStepOptionalStart undo from this step downward (1–9). Default: 9
-StopAfterStepOptionalStop undo at this step. Default: 1
-AutoConfirmOptionalSkip interactive confirmation prompts

Examples

# Dry run first — review what will be removed .\Undo-ACS-TPE-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -DryRun # Full undo steps 9 → 1 .\Undo-ACS-TPE-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json # Undo only steps 9–7 (remove assignment, license, RA — leave routes/gateway) .\Undo-ACS-TPE-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -StartAtStep 9 -StopAfterStep 7 # Undo only steps 3–2 (remove routes and gateway) .\Undo-ACS-TPE-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -StartAtStep 3 -StopAfterStep 2

07   Flip to Teams

Invoke-FlipToTeams-v14.ps1
Cutover

Day-2 re-cutover from ACS back to Teams after a rollback. Requires that Steps 1–9 are already completed (gateway, routes, and RAs must exist).

Steps

  • A
    Assign Teams Phone Numbers
    Calls Set-CsPhoneNumberAssignment for each number, linking it to its Teams Resource Account (Object IDs from ra-objectids.json).
  • B
    Toggle Routing ACS → Teams
    Calls Toggle-AcsTeamsRouting-v14.ps1. Disables ACS trunk, enables Teams gateway.
  • C
    Update D365 Phone Type ACS → TPS
    Calls Invoke-MigrateTpsPhoneNumber-v14.ps1 per number: sets D365 type to Teams, links RA, triggers CCaaS sync.

Parameters

ParameterRequiredDescription
-ConfigPathRequiredPath to the config JSON
-PhoneNumbersOptionalSpecific numbers to flip (e.g. "+12069990060"). Default: reads ra-objectids.json
-DryRunOptionalShow plan without making changes

Examples

# Dry run .\Invoke-FlipToTeams-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -DryRun # Flip all numbers from this migration run .\Invoke-FlipToTeams-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json # Flip a specific number only .\Invoke-FlipToTeams-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -PhoneNumbers "+12069990060"

08   Flip to ACS (Rollback)

Invoke-FlipToACS-v14.ps1
Rollback

Rolls back routing from Teams to ACS. Can be run at any time after Steps 10–11 have completed. Phone numbers are discovered automatically from D365 (all numbers with type=Teams).

Steps

  • A
    Toggle Routing Teams → ACS
    Calls Toggle-AcsTeamsRouting-v14.ps1. Disables Teams gateway, re-enables ACS trunk with original routes.
  • B
    Remove Teams Phone Number Assignments
    Calls Remove-CsPhoneNumberAssignment per number. Required to prevent D365 CCaaS background sync from re-linking the Teams RA.
  • C
    Update D365 Phone Type TPS → ACS
    Calls Invoke-MigrateTpsPhoneNumber-v14.ps1 per number: sets D365 type to ACS, clears Teams RA link, triggers sync.

Parameters

ParameterRequiredDescription
-ConfigPathRequiredPath to the config JSON
-PhoneNumbersOptionalSpecific numbers to flip. Default: queries D365 for all numbers with type=Teams
-DryRunOptionalShow plan without making changes

Examples

# Dry run .\Invoke-FlipToACS-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -DryRun # Roll back all Teams numbers to ACS .\Invoke-FlipToACS-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json # Roll back specific numbers .\Invoke-FlipToACS-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -PhoneNumbers "+12069990060","+12069990070"

09   Toggle Routing

Toggle-AcsTeamsRouting-v14.ps1
Supporting

Low-level routing toggle. Auto-detects current routing direction (ACS or Teams) and switches to the other side. Called by the flip scripts and Step 10 of migration. Can also be run standalone.

Auto-detect: ACS enabled + Teams disabled → flips to Teams. Teams enabled + ACS disabled → flips to ACS. If both or neither are active, the script errors out.

Parameters

ParameterRequiredDescription
-ConfigPathRequiredPath to the config JSON (needs AcsConnectionString, SbcFqdn)
-AutoConfirmOptionalSkip Y/N prompt (used when called from other scripts)
.\Toggle-AcsTeamsRouting-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json

10   Migrate Phone Number (D365)

Invoke-MigrateTpsPhoneNumber-v14.ps1
Supporting

Updates a single phone number's type and RA link in D365. Called by the flip scripts and Step 11 of migration. Can be run standalone for individual number fixes.

Parameters

ParameterRequiredDescription
-OrgUrlRequiredD365 org URL, e.g. https://contoso.crm.dynamics.com
-PhoneNumberRequiredE.164 format, e.g. +14255550100
-DirectionRequiredACS_TO_TPS or TPS_TO_ACS
-TeamsResourceAccountObjectIdOptionalRA ObjectId GUID for ACS_TO_TPS (from ra-objectids.json)
-DryRunOptionalShow current record state without patching
# Migrate ACS → Teams with explicit RA link .\Invoke-MigrateTpsPhoneNumber-v14.ps1 -OrgUrl "https://contoso.crm.dynamics.com" -PhoneNumber "+14255550100" -Direction ACS_TO_TPS -TeamsResourceAccountObjectId "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx" # Roll back Teams → ACS .\Invoke-MigrateTpsPhoneNumber-v14.ps1 -OrgUrl "https://contoso.crm.dynamics.com" -PhoneNumber "+14255550100" -Direction TPS_TO_ACS

11   Utility Scripts

Update-PhoneNumberType-v14.ps1

Lower-level D365 phone number record patcher. Directly sets msdyn_phonenumbertype, msdyn_ocphonenumbersource, and msdyn_teamsresourceaccount. Use Invoke-MigrateTpsPhoneNumber-v14.ps1 instead for most cases (it auto-discovers the provider setting).

.\Update-PhoneNumberType-v14.ps1 -OrgUrl "https://contoso.crm.dynamics.com" -PhoneNumber "+14255550100" -Direction ACS_TO_TPS -TeamsResourceAccount "guid" .\Update-PhoneNumberType-v14.ps1 -OrgUrl "https://contoso.crm.dynamics.com" -PhoneNumber "+14255550100" -Direction TPS_TO_ACS

Repair-D365PhoneRecord-v14.ps1

Diagnoses and repairs D365 phone number records that disappear from the CSAC UI after an undo. Checks for orphaned RA links, wrong phone number source, or inactive state (statecode=1). Use -Fix to apply repairs.

# Diagnose only (no changes) .\Repair-D365PhoneRecord-v14.ps1 -ConfigPath .\config.json -PhoneNumbers +12069990030 # Diagnose and fix .\Repair-D365PhoneRecord-v14.ps1 -ConfigPath .\config.json -PhoneNumbers +12069990030 -Fix # Fix all numbers .\Repair-D365PhoneRecord-v14.ps1 -ConfigPath .\config.json -Fix

Sync-TeamsPhoneNumbers-v14.ps1

Triggers CCaaS_SynchronizePhoneNumbers in D365 — the equivalent of clicking the "Sync from Azure" button in the CSAC UI. Run after any phone number type change if D365 doesn't reflect the new state.

.\Sync-TeamsPhoneNumbers-v14.ps1 -OrgUrl "https://contoso.crm.dynamics.com"

Get-TeamsProviderSetting-v14.ps1

Queries D365 for the active Teams communication provider setting and returns the CommsProviderId GUID. Useful for debugging D365 sync issues.

.\Get-TeamsProviderSetting-v14.ps1 -OrgUrl "https://contoso.crm.dynamics.com"

Fix-AcsRoutePattern-v14.ps1

Updates the ACS route pattern regex on the SBC FQDN. Run if the auto-generated regex does not match your phone numbers after migration.

.\Fix-AcsRoutePattern-v14.ps1 -ConfigPath .\config.json -DryRun .\Fix-AcsRoutePattern-v14.ps1 -ConfigPath .\config.json

Set-AcsSbcFqdn-v14.ps1

Updates the SBC FQDN in the ACS trunk configuration. Run if the FQDN needs to be changed after initial setup.

Add-AcsTrunkDisabled-v14.ps1

Manually records an ACS trunk FQDN in acs-trunk-disabled.json. Used when the migration Step 2 did not automatically capture the disabled trunk (e.g. after a partial run).

Test-DomainRegistration-v14.ps1

Verifies that the custom domain is registered and verified in Entra ID. Run before Step 4 or to diagnose RA creation failures caused by an unverified domain.

Archive-TpeRuns-v14.ps1

Cleans up the working directory by moving old HTML run logs and backup JSON files into Backup-Run\ and Backup-Config-json\. Always keeps the latest config, tpe-status.html, and files needed by rollback scripts.

.\Archive-TpeRuns-v14.ps1 -DryRun .\Archive-TpeRuns-v14.ps1

13   Quick Reference

First-Time Migration (clean environment)

# 1. Generate config .\New-AcsTpeConfig-v14.ps1 -Domain "cbg-voice.contoso.com" # 2. Dry run .\Invoke-ACS-TPE-Full-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -DryRun # 3. Run migration .\Invoke-ACS-TPE-Full-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json

Roll Back to ACS

.\Invoke-FlipToACS-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -DryRun .\Invoke-FlipToACS-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json

Re-Cut to Teams

.\Invoke-FlipToTeams-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -DryRun .\Invoke-FlipToTeams-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json

Full Teardown (reset to step-1 clean state)

# Step 1: Roll back routing + D365 .\Invoke-FlipToACS-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json # Step 2: Remove all Teams objects created during migration .\Undo-ACS-TPE-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -DryRun .\Undo-ACS-TPE-Migration-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json

Fix D365 After Rollback (numbers missing from CSAC)

.\Repair-D365PhoneRecord-v14.ps1 -ConfigPath .\new-acs-tpe-config-v14.11.0.json -Fix
